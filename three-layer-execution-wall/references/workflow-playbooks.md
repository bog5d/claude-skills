# Workflow Playbooks

## 1. 系统诊断工作流

适用：
- 看看系统现状
- 判断服务是否正常
- 找出哪里有问题

步骤：
1. 明确诊断对象与成功标准
2. 读取当前状态 / 配置 / 日志 / 健康检查
3. 做低风险验证与抽样
4. 定位异常点
5. 区分现象、原因、证据
6. 输出诊断结论与建议

交付重点：
- 结论先说
- 已验证项
- 根因候选
- 风险与下一步

---

## 2. API 评估工作流

适用：
- 看接口能不能用
- 判断 API 成熟度
- 做接入评估

步骤：
1. 检查基础连通性
2. 读文档 / schema / OpenAPI
3. 抽样调用低风险接口
4. 看成功结构、失败结构、鉴权、延迟
5. 总结能力边界与接入建议
6. 输出评估报告

交付重点：
- 是否可用
- 返回结构是否规范
- 已验证接口
- 风险与接入建议

---

## 3. 代码修改工作流

适用：
- 改 bug
- 改配置
- 改代码逻辑

步骤：
1. 先读目标文件与上下文
2. 明确修改范围
3. 优先小改，必要时再上复杂改动工具
4. 修改后做校验 / 测试 / diff 检查
5. 总结改了什么与为什么
6. 输出改动说明

交付重点：
- 修改目标
- 实际改动
- 验证方式
- 剩余风险

---

## 4. 故障排查工作流

适用：
- 某个流程失败
- 某个服务异常
- 某个工具报错

步骤：
1. 先收集错误现象
2. 区分是配置、权限、参数、依赖还是环境问题
3. 做最小复现实验
4. 修复一个变量后再复测
5. 验证是否真正恢复
6. 输出故障结论与修复建议

交付重点：
- 故障现象
- 根因判断
- 修复动作
- 是否验证恢复

---

## 5. 研究报告工作流

适用：
- 调研
- 对比
- 趋势分析
- 方案研究

步骤：
1. 明确研究问题与维度
2. 搜集权威与高质量来源
3. 交叉验证关键事实
4. 形成结构化观察
5. 区分事实 / 推断 / 建议
6. 输出研究报告

交付重点：
- 核心结论
- 依据
- 差异点
- 建议行动

---

## 6. 本地项目理解工作流

适用：
- 理解本地项目结构
- 接手已有代码库
- 快速掌握入口、依赖、模块关系

步骤：
1. 看目录结构
2. 识别入口文件、配置文件、依赖定义
3. 阅读关键模块与 README / context 文件
4. 归纳项目用途、核心模块、运行方式
5. 标出风险区与不确定点
6. 输出项目理解说明

交付重点：
- 项目做什么
- 主要结构
- 关键入口
- 运行 / 修改注意点
