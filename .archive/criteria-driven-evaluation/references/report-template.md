# 评估报告模板

基于 `criteria-driven-evaluation` 技能生成的候选人（或方案/供应商）评估报告应包含以下结构。

## 报告结构

### 封面
- 标题：「候选人筛选评估报告」或对应场景标题
- 副标题：岗位/场景说明（如"投融资事务代表（应届）· 简历筛选与多维评估"）
- 脚注：评估日期、候选总数、评估模型名称

### 第一节：评估模型说明
- 完整维度表格（维度名 | 权重 | JD原文对应）
- 核心结论（3-5条，概述整体发现）
- 特征总结（如"海归+实战型人才稀缺""6-7分段断档明显"）

### 第二节：逐人详析
每人至少包含：
- **基本信息**：姓名、性别、年龄、联系方式、学历
- **"为什么适合"长文分析**：这是最重要的部分——结合 JD 原文信号，用候选人的具体简历内容论证匹配度。段首用 JD 原文打头，然后对接到候选人的具体经历。
- **评分表**：维度名 | 得分/10 | 评分依据（含简历原文引用）
- **综合评价一句话**

对于低分段候选人（如 <6.0/10），可简化为表格条目，标注致命短板。

### 第三节：综合排名总表
- 全量候选人排序表，含：排名、姓名、得分、性别、推荐等级、核心匹配点
- 前3名用高亮色标出
- 低分段用灰色标出

### 第四节：分层推进建议
- **第一优先**：立即面试（3个工作日内），含具体考察要点
- **第二优先**：批次面试或储备观察
- **建议搁置**：标注原因

### 第五节（可选）：定制面试问题
当用户提供已约面试名单后，为每人出3-5个高价值问题，问题必须：
- 结合该候选人简历中的具体信号/风险
- 针对 JD 核心维度（如"对外不怵"→ 问"说一个你主动搞定难搞的人的经历"）
- 不是通用问题模板
