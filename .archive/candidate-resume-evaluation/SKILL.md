# 候选人简历评估

## 铁律（最高优先级）

**评分模型必须从 JD 重建，禁止使用通用金融/技术岗模型。** 用户 2026-06-09 明确纠正：上一版用"社招金融分析师"8 维模型评估"应届投融资事务代表"是完全错误的。

---

## 标准流程

### Phase 1：申请 JD（如果用户未发）

```
请把岗位 JD 发给我，我先理解岗位要什么样的人再建评分模型。
```

### Phase 2：解析 JD → 建立定制评分模型

从 JD 中提取：
1. **硬性条件**（学历、专业、经验年限）
2. **核心软性要求**（JD 中明确强调的特质，如"对外不怵""学习力强"）
3. **加分信号**（JD 明确列出的加分项）
4. **排除信号**（JD 明确排除的特征）

**权重分配原则**：
- JD 中排在最前面、用最多篇幅描述的 → 最高权重
- JD 说是"更重要的是…"的 → 高于硬性条件
- JD 说是"加分但不是必须"的 → 低权重
- JD 说"不适合的信号" → 作为负分/排除项

> ❌ **禁止**：复用任何预设的通用评分模型。每次评估必须从 JD 重建。

### Phase 3：解析简历 → 标准化提取

每份简历提取：
- 姓名、性别、年龄、联系方式
- 教育背景（学校+专业+学历+GPA/排名）
- 工作/实习经历（**原文引用**——用户要求报告中包含原始简历内容）
- 项目经历（同上，原文引用）
- 证书与技能
- 语言能力

使用 `fitz`（PyMuPDF）提取 PDF 文本。

### Phase 4：逐人 JD 对齐评分

对照 JD 的每个维度，基于简历**原文证据**打分（不是印象分）。

关键原则：
- 每条分数必须附"简历原文依据"
- "对外不怵"不能只看 title，要看实际工作内容——机构渠道维护 ≠ 主动开拓
- 应届生不能因"零经验"而被过度扣分（如果 JD 本身就是招应届生）

### Phase 5：生成报告

**报告必须包含：**

1. **封面**：岗位名称 + 评估日期 + 候选人总数
2. **评估模型说明**：维度、权重、JD 原文对应
3. **核心结论**：梯队分布 + 整体特征
4. **逐人详析**（≥ 阈值分）：
   - 基本信息（含性别——用户 2026-06-09 明确要求）
   - 教育背景
   - "为什么适合这个岗位"长文分析
   - 维度评分表（含 JD 原文依据）
   - 简历关键原文引用
5. **低分段简表**（< 阈值分）：仅表格，无详析
6. **综合排名全表**：含性别、核心竞争力、短板
7. **面试与录用建议**：分层策略

**报告格式**：
- 输出 Word + PDF 双份（用户偏好）
- 中文排版，SimSun/SimHei 字体
- 评估工具标注：Hermes Agent
- 评分标准标注：JD 对齐 X 维模型

### Phase 6：本地归档

所有简历 PDF 按 `{得分}_{姓名}.pdf` 命名存入 `~/.hermes/cache/documents/候选人简历库/`。

## 已知教训（必须遵守）

1. **应届岗 ≠ 社招岗**：经验相关性权重不能最高，对外能量/学习力/韧性才是 JD 重点
2. **性别信息必含**：用户 2026-06-09 明确批评"有些不知道他们性别"
3. **原文引用不可省略**：用户要的是"引用了他的真实的简历当中内容"
4. **低分者不展开**：用户说"太低了也就不用了"，低于阈值只放简表
5. **证书只在 JD 要求时才加权重**：JD 说"更看重思维而非专业标签"时，CFA/ACCA 不能大幅拉分
6. **"对外能量"要看本质**：机构渠道维护（等客户上门）≠ 主动开拓（搞定人），前者分数不能太高

- 中文字体：STHeiti / PingFang SC
