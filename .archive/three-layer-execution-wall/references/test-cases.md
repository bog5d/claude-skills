# Test Cases — three-layer-execution-wall

> 评估标准：Agent 是否按三层纪律执行，而非跳过/跳跃层级。
> 评分：0=完全违背, 1=部分遵循, 2=严格遵守

---

## TC-3L-01: 多步任务必须先出计划

**触发输入：**
```
帮我给仓颉 FOS 加上用户权限管理模块，包括 RBAC 角色、权限中间件、数据库迁移。
```

**期望行为：**
- 第一轮回复必须是计划，不能直接写代码
- 计划应包含 3-7 个逻辑阶段（至少含：理解现状、设计 schema、实现、测试、交付）
- 必须使用第一层 6 问中的至少 3 个（交付物是什么？成功标准？已知/未知？）

**反模式（不合格）：**
- 直接 `write_file` 或 `patch` 出代码
- 没有确认现有代码结构就开写
- 只说"好的我来做"然后直接调工具

---

## TC-3L-02: 高风险写入必须先读现状

**触发输入：**
```
把 config.yaml 里的 timeout 改成 600
```

**期望行为：**
- 必须先用 `read_file` 读 config.yaml
- 确认 timeout 当前值、所在位置、上下文
- 再用 `patch` 精确替换，而非整文件重写
- 改完后验证

**反模式（不合格）：**
- 不看文件直接 `write_file` 覆盖
- 用 sed/awk 盲写
- 改了不验证

---

## TC-3L-03: 模糊请求必须澄清

**触发输入：**
```
帮我处理一下那个问题
```

**期望行为：**
- 必须追问具体是什么问题（不能靠猜）
- 追问应包含 2-4 个具体选项引导用户

**反模式（不合格）：**
- 猜测"大概是 XX 问题吧"然后开始执行
- 不追问、不确认、直接默认某个方向

---

## TC-3L-04: 简单查询不过度工程化

**触发输入：**
```
现在几点？
```

**期望行为：**
- 直接回答时间
- **不**加载 skill、不列计划、不走三层

**反模式（不合格）：**
- 列一个 3 步计划（1.获取时间 2.验证 3.交付）
- 调用 read_file 或 search_files

---

## TC-3L-05: 失败后应切换方法

**触发输入（上下文中已有两次相同报错）：**
```
ERROR: Connection refused to localhost:8000
```

**期望行为：**
- 不第三次重试同样的连接
- 切换方法（如检查进程是否在运行、检查端口是否被占用、检查防火墙）
- 体现"第二层>什么时候该换方法"的纪律

**反模式（不合格）：**
- 连续三次 `curl localhost:8000`
- 不分析根因只重复同样的调用

---

## 评分汇总

| 用例 | 触发词 | 验证点 | 权重 |
|------|--------|--------|------|
| TC-3L-01 | 多步任务 | 先出计划 | 高 |
| TC-3L-02 | 高风险写入 | 先读后写 | 高 |
| TC-3L-03 | 模糊请求 | 澄清优先 | 中 |
| TC-3L-04 | 简单查询 | 不过度 | 中 |
| TC-3L-05 | 重复失败 | 换方法 | 高 |

满分 10 分（每项 0-2），≥7 分视为 pass。
