# Task Type Router

## 作用

在复杂任务开始前，先做一次轻量任务识别，决定默认工作路径。

目标：

- 少走错第一步
- 少把研究当执行
- 少把诊断当修改
- 少把产出类任务做成一堆日志

---

## 必须产出的 4 个内部字段

在开始复杂任务前，先快速判断：

- `task_type`：任务主类型
- `risk_level`：风险等级（low / medium / high）
- `deliverable`：最终交付物
- `first_move`：默认第一动作

不要全展示给用户，但内部要明确。

---

## 六类任务

### 1. diagnose

适用：诊断 / 排障 / 现状评估 / 原因分析

信号词：

- 怎么回事
- 为什么不行
- 帮我看看现状
- 排查
- 分析原因
- 查 bug / 查异常

默认路径：

- 先读
- 先查证据
- 先抽样验证
- 不直接改
- 输出时先结论后证据

默认第一动作：`先读 / 先查 / 先抽样`

---

### 2. execute

适用：修改 / 修复 / 处理 / 更新 / 落地执行

信号词：

- 帮我改
- 帮我修
- 更新一下
- 处理掉
- 改代码 / 改配置 / 改文件

默认路径：

- 先读原状
- 再确定范围
- 小改优先
- 改完验证
- 输出改动与验证结果

默认第一动作：`先读原始状态`

---

### 3. research

适用：研究 / 搜索 / 对比 / 方案调研

信号词：

- 调研
- 对比
- 研究
- 看看有哪些方案
- 差异
- 趋势

默认路径：

- 先明确维度
- 先搜可信来源
- 区分事实 / 推断 / 建议
- 最后结构化总结

默认第一动作：`先定维度 / 先搜来源`

---

### 4. produce

适用：写作 / 方案 / 报告 / 总结 / 文案 / 成品整理

信号词：

- 写一个
- 帮我整理
- 做个报告
- 做个方案
- 生成总结

默认路径：

- 先定交付物
- 盘点材料
- 不足则补查
- 用模板输出成品

默认第一动作：`先定交付物与材料缺口`

---

### 5. automate

适用：自动化 / 编排 / 批量 / 定时 / 长流程

信号词：

- 自动处理
- 批量执行
- 串起来
- 跑一套流程
- 定时
- cron

默认路径：

- 先拆阶段
- 小样本验证
- 说明副作用和恢复方式
- 最后单独验收

默认第一动作：`先拆计划 / 先小样本`

---

### 6. decide

适用：澄清 / 决策支持 / 方向选择

信号词：

- 怎么选
- 你建议哪个
- 帮我判断
- 该不该
- 哪个更适合

默认路径：

- 先列选项
- 明确判断标准
- 优先给建议
- 真阻塞时再问用户

默认第一动作：`先列选项和标准`

---

## 风险等级判断

### low

- 只读
- 单步
- 无外部副作用

### medium

- 轻量写入
- 小范围修改
- 需要验证但可回滚

### high

任一满足即 high：

- 批量修改
- 覆盖文件
- 改系统配置
- 发送消息
- 创建 cron / 调度
- 重启 / 部署 / 删除
- 外部系统副作用未知

---

## 路由优先级

当多个类型同时成立时，主类型优先级如下：

1. `decide`
2. `diagnose`
3. `execute`
4. `automate`
5. `research`
6. `produce`

---

## 默认路由表

| task_type | 默认第一动作 | 输出重点 |
|---|---|---|
| decide | 列选项和标准 | 建议与权衡 |
| diagnose | 读 / 查 / 抽样 | 结论、证据、原因 |
| execute | 读原状 | 改动、验证、风险 |
| automate | 拆计划 / 小样本 | 流程、状态、恢复 |
| research | 定维度 / 搜来源 | 结论、依据、比较 |
| produce | 定交付物 / 材料缺口 | 成品质量 |

---

## 最小执行协议

复杂任务开始时，先在内部写出一句：

`task_type=<...>; risk=<...>; deliverable=<...>; first_move=<...>`

然后再进入三层执行墙。

这一步不需要很长，但必须做。
