# 神力股份案例：角色假设错误的教训

## 场景

用户描述：「神力股份实控人持有25%，出资方去谈，怎么设计退出方案」

## 第一次错误

Agent 直接假设「出资方是收购方，要买控制权」，写了一整套控制权收购方案（表决权委托、私募EB等六方案）。

## 用户纠正

实际角色：
- 原实控人 → 卖25%留5%
- **新实控人**（产业方创始人）→ 要买25%，但没钱，自己凑8亿（6亿配资+2亿个人出资人）
- **出资人**（被谈的对象）→ 借1-2亿给新实控人，不参与经营，要安全+收益

角色完全反了。Agent的方案变成废纸。

## 根因

三层执行墙的 Layer 1 "必过的6个问题"里，缺少一个关键问题：

**「交易/方案中涉及几个角色？每个角色的诉求是什么？谁的钱、谁的股、谁锁、谁不锁？」**

## 改进

在执行墙的 Layer 1 调研步骤中，面对涉及多方利益的复杂场景（投融资、并购、合作方案等），必须先做**角色矩阵**确认：

| 角色 | 出什么 | 拿什么 | 锁不锁 | 核心诉求 |
|------|--------|--------|:--:|------|
| A | | | | |
| B | | | | |

向用户确认矩阵无误后，再启动方案设计。
