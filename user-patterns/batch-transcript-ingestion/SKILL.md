# 分批投递会议转写处理（波总副官管线）

## 触发条件

波总把同一场会议/口述分 2-3 段投递（常见模式：先发一段"你先整理"，之后继续补发续篇，文末可能附名片/联系方式）。2026-08-19 龚德仁交流三部分投递为首次完整案例。

## 正确流程

```
每段到达：
  1. 追加到同一 raw 文件（`## 第X部分（同一场会议续篇，波总X次投递）`标记分隔，raw 保真一字不改）
  2. 若第一批拆解已在跑：不等不kill，raw 继续追加
第一批完成（收到 notify）：
  3. 更新补拆任务书：检查第一批拆解卡是否已覆盖后续部分（覆盖则只补缺口）；
     列出后续部分独有事实（编号列出，供提炼定位）；
     更新说话人映射确认信息；更正术语
  4. 等第一批 commit 完再派补拆（避免两个 Cursor 同时写仓库）
  5. 监工验证：validate 基线零新增 + commit 存在 + 关键字段入卡
```

## 说话人身份确认（ASR 转写不定死）

- **确认格式（2026-08-21 波总定，强制）**：需要向波总确认说话人归属时，必须逐人写「说话人N主要提到了：……（内容要点摘要，列事件/项目/自述细节），我推测他是XX，对不对？」——波总看内容要点即可回答，不用回听录音。禁止只问「说话人N是谁」。要点摘要要有区分度（该人独有的第一人称自述、项目名、机构名），别写废话。
- **名片/联系方式=最强证据**：波总文末附的名片（头衔/电话/邮箱/地址）与转写中自述吻合即可坐实映射（实例：说话人5 说"我是主任法人代表"+名片=临空中心主任 → 坐实=龚德仁）
- 其余说话人映射存疑一律标[待确认]，不猜不编
- 人名/机构名 ASR 纠错（微大星空→微纳星空、蓝京→南京、新华→新化、深长探测→深空探测），纠错后**专业术语必须波总确认**（实例：水导 曾被理解为"水下导航"，波总纠正=水导激光 water-guided laser，水柱引导激光精密加工技术）

## 人名确认的坑（2026-08-21 波总两次发火教训，铁律）

- **波总自己发来的消息里的名字也可能是语音转写误**（实例：波总语音误传"李毅"，差点推翻正确的"说话人1=李云云"——其发言内容全是楚宏资本项目，与李毅毫无关联）。处理：用户消息中的人名改动若与内容要点/已知人物矛盾（内容全是甲的独特自述却改名乙），**先反问确认再落库**，不要无条件推翻内容要点佐证的判断。已落库的错误用"反向修正任务"撤销，不留歧义。
- **已定名实体以记忆/仓库为准，转写变体不改名、禁止来回改**（实例：泽天董事长=唐兴二字已定，"唐鑫"等变体一律视为 ASR 误；波总原话"你他妈能不能定下来是这两个字"）。转写里出现的新变体≠修正信号——先查记忆/仓库已有定名，再判断是否需要确认。
- **高频 ASR 映射表**维护在仓库 `知识库/实体索引/conflicts.md`（郭总=波总、唐鑫=唐兴、余世勋=俞铁成、李云颖=李云云、广汇=广慧、一支资本=易居资本、陈启伟=陈琦伟、中国旭创=中际旭创…）。处理新录音先查表；发现新映射立即追加进表。

## 与副官管线衔接（OBS 仓库 AGENTS.md 流程）

raw → clean（ASR 纠错带[修正]标注，说话人映射[待确认]）→ 拆解卡（新事实带来源+发言人编号/新认知/行动项/待确认）→ 人脉卡 V2 八维（含名片全字段）→ 互动日志/视图 → OPEN.md 待办 → 副官系统 V3（operating_state.json 主线+脚本重生成）→ 台账/INDEX → validate（基线 134 errors 零新增）→ commit+push（0/0 分叉）。

## 坑

- 补拆任务书忘了检查第一批覆盖范围 → 重复拆解或遗漏；任务书开头必须要求"先确认已覆盖，未覆盖则补"
- 说话人编号跨段不连续（说话人5/9/10 出现）——是转写器分段独立编号，不是新人物，别据此开新卡
- **同场内说话人 ID 分离误差**：同一人被 ASR 拆成两个 ID（实例：波总确认"说话人1=龚德仁"后，说话人5 的自述"我是主任法人代表/我6月份才任命去管那个"也完全吻合——疑 1/5 为同一人）。判断信号=两个 ID 的发言都含同一人的第一人称职务自述。处理：以波总确认的 ID 为准，另一 ID 标注"疑同人（ASR 分离误差，待最终确认）"，**不得建新卡**
- 波总中间插话纠正术语（如"水导是水导激光"）→ 立即改补拆任务书+向波总确认理解，raw 不改

## 波总拍板后的修正/补充两段式

拆解完成后波总陆续给出确认（说话人是谁/机构全称/时间线/方案选择）。**不要攒着也不要不落库**，分两类任务派 Cursor：

1. **修正任务**（纠正已落库的错误）：任务书列明"仅修正 3 项"逐条写清正确值+证据；要求先 git pull 确认 HEAD 再改；raw 一字不改；validate 基线零新增；输出修正清单+commit hash。实例：说话人1=龚德仁（原误落 5）、杭州基金法定名=青岛经协恒兴创业投资基金合伙企业（有限合伙）、注册时间线改 9 月底 10 月初。
2. **补充任务**（新拍板信息落库）：新人物建卡（如说话人2=李红兵=波总合伙人 → 人脉卡 V2+entities+relations+互动日志）、方案拍板（T 待办升级为已定案）、机构全称（ASR 变体统一）、决策记录（含风险已告知仍拍板保留的项）。每批等前一批 commit 完成再派（防 Cursor 抢仓库）。
