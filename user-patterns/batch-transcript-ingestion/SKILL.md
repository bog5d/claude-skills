# 分批投递会议转写处理（波总副官管线）

## 触发条件

波总把同一场会议/口述分 2-3 段投递（常见模式：先发一段"你先整理"，之后继续补发续篇，文末可能附名片/联系方式）。2026-08-19 龚德仁交流三部分投递为首次完整案例。

## 正确流程

```
每段到达：
  1. 追加到同一 raw 文件（`## 第X部分（同一场会议续篇，波总X次投递）`标记分隔，raw 保真一字不改）
  2. 若第一批拆解已在跑：不等不kill，raw 继续追加
第一批完成（收到 notify）：
  3. 更新补拆任务书：检查第一批拆解卡是否已覆盖后续部分（覆盖则只补缺口）；
     列出后续部分独有事实（编号列出，供提炼定位）；
     更新说话人映射确认信息；更正术语
  4. 等第一批 commit 完再派补拆（避免两个 Cursor 同时写仓库）
  5. 监工验证：validate 基线零新增 + commit 存在 + 关键字段入卡
```

## 说话人身份确认（ASR 转写不定死）

- **名片/联系方式=最强证据**：波总文末附的名片（头衔/电话/邮箱/地址）与转写中自述吻合即可坐实映射（实例：说话人5 说"我是主任法人代表"+名片=临空中心主任 → 坐实=龚德仁）
- 其余说话人映射存疑一律标[待确认]，不猜不编
- 人名/机构名 ASR 纠错（微大星空→微纳星空、蓝京→南京、新华→新化、深长探测→深空探测），纠错后**专业术语必须波总确认**（实例：水导 曾被理解为"水下导航"，波总纠正=水导激光 water-guided laser，水柱引导激光精密加工技术）

## 与副官管线衔接（OBS 仓库 AGENTS.md 流程）

raw → clean（ASR 纠错带[修正]标注，说话人映射[待确认]）→ 拆解卡（新事实带来源+发言人编号/新认知/行动项/待确认）→ 人脉卡 V2 八维（含名片全字段）→ 互动日志/视图 → OPEN.md 待办 → 副官系统 V3（operating_state.json 主线+脚本重生成）→ 台账/INDEX → validate（基线 134 errors 零新增）→ commit+push（0/0 分叉）。

## 坑

- 补拆任务书忘了检查第一批覆盖范围 → 重复拆解或遗漏；任务书开头必须要求"先确认已覆盖，未覆盖则补"
- 说话人编号跨段不连续（说话人5/9/10 出现）——是转写器分段独立编号，不是新人物，别据此开新卡
- 波总中间插话纠正术语（如"水导是水导激光"）→ 立即改补拆任务书+向波总确认理解，raw 不改
