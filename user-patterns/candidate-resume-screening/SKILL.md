# candidate-resume-screening — 简历动态筛选与评估报告

波总逐份发送简历 → 同一标准动态打分 → 维护实时排名表 → 最终输出含原文引用的详细报告（DOCX+PDF）。报告需可直接转合伙人审阅。

## 核心铁律

### 1. 报告必须包含简历原文引用
波总原话："不然要往深看，还不知道内容呢，就只有结论，也没有太多的原始信息也不好弄。"

每份候选人报告必须包含：
- 教育背景原文（学校、专业、GPA、课程）
- 工作/实习经历的**原文引用**（用「原文引用」标签标注）
- 项目经历的**原文引用**
- 证书资质的完整列举
- 技能与语言的完整列举

**不能只写"AUM 1958万"这种提炼**——必须附带原文语境，让合伙人不翻原始简历也能判断。

### 2. 同一标准，动态追加
- 评分维度和权重**全程不变**
- 每个新简历追加进表，不重新打分已有候选人
- 得分即文件名（如 `8.4_张元卿.pdf`），方便排序

### 3. 最终输出：DOCX + PDF 双份
- 使用 `formal-document-generator` 技能中的 Phase 3 路径 B（DOCX → HTML → weasyprint）
- 文件存放于 `~/.hermes/cache/documents/候选人简历库/`

## Phase 1: 逐一解析简历

用 pymupdf (fitz) 提取 PDF 文本：

```bash
python3 -c "
import fitz
doc = fitz.open('简历文件.pdf')
for i, page in enumerate(doc):
    text = page.get_text()
    print(f'=== PAGE {i+1} ===')
    print(text)
doc.close()
"
```

提取关键字段：姓名、电话、邮箱、性别、年龄、学历、GPA、课程、证书、工作经历、项目经历、技能、语言。

## Phase 2: 8维加权评分

默认维度与权重（适用于投资/融资岗位）：

| 维度 | 权重 | 评分要点 |
|------|:----:|------|
| 学历匹配度 | 10% | 专业相关性 + 院校档次 |
| 经验相关性 | 25% | 与目标岗位的直接经验匹配 |
| 业绩表现 | 20% | 可量化的业务成果 |
| 专业资质 | 10% | 持证情况 |
| 客户服务能力 | 15% | KYC/转化/维护 |
| 数据分析能力 | 10% | Python/SQL/Excel/建模 |
| 合规风控意识 | 5% | 合规经验/风控/审计 |
| 综合发展潜力 | 5% | 年龄/英语/学习力/成长性 |

**如需调整维度，先与波总确认**。确认后全程不动。

每维度 1-10 分，加权合计 = 综合得分。必须写评分依据（1-2句话，引用简历原文支撑）。

## Phase 3: 实时排名表

每追加一个候选人后，输出精简排名表（Telegram 消息中）：

```
# | 姓名 | 得分 | 推荐度 | 核心竞争力
1 | 张元卿 | 8.4 | 🔥 强推 | ...
2 | 吴素 | 7.4 | ✅ 推荐 | ...
```

推荐度标识：🔥 强推 (≥8.0) / ✅ 推荐 (≥6.5) / 🟡 备选 (≥5.0) / ⚠️ 短板 (≥4.0) / ❌ 不推荐 (<4.0)

## Phase 4: 本地归档

每收到一份简历，同步归档到本地：

```bash
mkdir -p ~/.hermes/cache/documents/候选人简历库
cp "原始文件.pdf" "候选人简历库/{得分}_{姓名}.pdf"
```

归档后 `ls -1 | sort -r` 验证排序。

## Phase 5: 生成详细报告（DOCX + PDF）

波总说"出一份详细的报告"时触发。报告结构：

1. **封面**：标题 + 日期 + 候选人总数 + 评估维度说明
2. **执行摘要**：维度权重表 + 核心结论（三梯队分类）+ 整体特征判断
3. **候选人逐人详析**（每人1页+）：
   - 基本信息（电话、邮箱、年龄、性别）
   - 🎓 教育背景（原文引用）
   - 📜 证书与资质
   - 💼 工作/实习经历（原文引用 + 量化业绩）
   - 📋 项目经历（原文引用）
   - 🛠 技能 & 语言
   - 📊 8维评分表（维度/得分/依据）
   - 💬 综合评价（1-2句话）
4. **综合排名总表**：排名/姓名/得分/推荐等级/核心竞争力/短板风险
5. **面试与录用建议**：第一二三优先级 + 整体判断

### 生成方式

使用 python-docx 生成 DOCX（参考 `formal-document-generator` Phase 2 的字体/样式规范），然后走 Phase 3 路径 B 转 PDF。

```bash
# 参考 formal-document-generator 技能获取完整 DOCX 生成模板
# 关键字体设置（macOS）：
# - 标题：STHeiti 18pt / 15pt / 13pt
# - 正文：PingFang SC 或 SimSun 11pt
# - 表格：PingFang SC 9pt
# - 着色表头：2F5496 背景 + 白色文字
```

### 报告特征
- 表格用 `Light Grid Accent 1` 样式
- 表头深蓝背景 (#2F5496) + 白色加粗字
- 前3名行浅绿高亮 (#E2EFDA)
- 页脚灰字标注生成时间和评估工具

## Pitfalls

- **不要只提炼数字**：报告必须包含简历原文引用，标注「原文引用」标签
- **不要中途改权重**：一旦开始，维度与权重全程锁定
- **不要跳过 PDF**：波总需要转发合伙人，必须同时出 DOCX 和 PDF
- **pymupdf vs OCR**：优先用 fitz 直接提取文本（PDF 从 Word/WPS 导出的都可直接读），只有扫描件才需要 OCR
- **weasyprint 中文**：CSS 必须显式声明中文字体（STHeiti/PingFang SC），否则 PDF 中文乱码
- **文件命名**：用 `{得分}_{姓名}.pdf` 格式，数字在前方便按分排序
