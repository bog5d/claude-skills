# 【项目名】工作区总规则 v1.0

## 0. 项目背景（接手必读）
- **来源**：【合作方/技术来源方是谁】
- **意图**：【这个项目要做成什么】
- **赛道/领域**：【一句话定位】
- **当前任务**：【如：商业计划书 / 尽调报告 / 研究综述】
- **工作模式**：多 Agent 并行。波总会不停扔随机材料进来，各 Agent 负责归档、分析、整合

## 1. 目录结构（固定，不许改结构本身）
```
00_INBOX/            ← 一切新材料先扔这里（唯一入口）
01_原始材料/          ← 已归档一手材料（只读！）
02_分析与洞察/        ← AI/人产出的分析
03_BP工程/            ← 交付物区【按项目改名：BP工程/尽调工程/交付物】
99_ARCHIVE/           ← 废弃/过期材料（不删，移到这里）
_RULES.md             ← 本文件
_LEDGER.md            ← 台账（只追加不修改）
```

## 2. 铁律（违反 = 返工）
1. 唯一入口：新材料一律先进 `00_INBOX/`
2. 原件不可变：`01_原始材料/` 只读；要批注 → 新文件放 `02_`
3. 先记账后收工：每次处理完材料必须追加 `_LEDGER.md`
4. 不删任何东西：不要的移 `99_ARCHIVE/`
5. 文件名规范：`YYYYMMDD_来源_描述.扩展名`
6. 分析产出双格式：正式分析 `.md`；需给波总看的另出截图/HTML
7. 口径统一：数字必须注明出处文件，禁止无出处编造

## 3. 来源枚举（按项目改这张表）
| 来源标签 | 含义 |

| 【来源A】 | 【如：技术提供方官方材料】 |

| 其他AI | 其他工具产出（描述注明工具名） |

## 4. 口述/录音转写处理规则
1. 原文一字不改存 `01_原始材料/口述与会议/`
2. 另出整理稿放 `02_` 对应目录，开头注明出处关系
3. 拿不准的词标 `【？】`，文末列待核实清单
4. 说话人标签错乱时按内容重新归属，整理稿开头给角色推断表

## 5. 多 Agent 协作纪律
- 接手第一件事：读本文件 + `_LEDGER.md` 尾部20行
- 收工前：更新 `_LEDGER.md`（做了什么/产出了什么/下一步建议），刷新 §6 当前状态
- 规则不够用：台账 `[RULE-GAP]` 区写建议等波总拍板，禁止私改规则
