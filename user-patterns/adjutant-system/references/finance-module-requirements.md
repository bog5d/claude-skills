## 核心设计决策（grillme 产出）

| 维度 | 决策 | 来源 |
|------|------|------|
| **核心驱动力** | 总债务数字下降 + 每周进度条推进 | 第一波Q1 |
| **MVP** | 还款记录 → 自动进度条 → 里程碑提醒 | 第一波Q2 |
| **深层痛点** | 混乱——太多笔，记不住到底欠多少 | 第一波Q3 |
| **致死风险** | 太复杂就弃用 → 零表单、零字段、一句话还款 | 第一波Q4 |
| **交互方式** | 自然语言：`还了花呗2000` → 自动识别+更新 | 第二波Q1 |
| **数据源策略** | Excel 记详细成因，系统追踪金额进度（双轨并行） | 第二波Q2 |
| **反馈节奏** | 每周日晚自动推送全景大盘 | 第二波Q3 |
| **零进展行为** | 照样报，纯数据 + 同期对比，不给压力 | 第三波Q1 |

## 技术实现

### 目录结构
```
~/.hermes/adjutant/finance/
├── debts.json              ← 债务清单（含历史余额快照）
├── transactions.json       ← 还款日志（date, debt_id, amount）
├── config.json             ← 元数据（起始日期、里程碑阈值）
├── snapshots/              ← 周度自动快照
│   └── 2026-W22.json
├── reports/                ← 生成的报告文件
└── scripts/
    └── finance.py          ← CLI：CRUD + 报告生成
```

### 交互协议

| 波总输入 | 系统行为 |
|----------|----------|
| `还了花呗2000` | 解析 → 匹配债务 → 扣减余额 → 即时确认反馈 |
| `我的债务` | 即时输出当前全景（总负债/进度/里程碑） |
| `新增债务 借了XX五万` | 新增债务条目 |
| （周日 21:00 cron） | 生成周报大盘图片 → 推送 Telegram |
| 无输入一周 | 照样报周报，加同期对比，不给压力话术 |

### NLP 解析规则
- 关键词：`还了` / `还` / `还款` → 还款操作
- 金额识别：中文数字 + 阿拉伯数字
- 债权人匹配：模糊匹配 debts.json 中的 creditor 字段
- 无法匹配时：列出候选让波总选

## 与其他系统的边界

- **副官任务系统**：财务独立于任务管理，不混入 status.json
- **债务提醒 ≠ 任务提醒**：还款到期提醒走财务子系统，不走 adjutant tasks
- **Excel 是主数据源**：详细成因、历史背景在 Excel，系统只追踪金额和进度
