# 主题素材包输出模板（只读梳理工作流）

> 2026-08-19 实战（南京雷达合资公司/跃壹科技素材包，输出 32KB/223 行至 /tmp/radar_collect.md）。
> 用途：用户要"梳理知识库中关于主题 X 的全部素材/输出素材包/做主题调研"时，按本文件快速定位与成稿。

## 1. 跨模块映射图（一个主题要扫哪些文件，按序）

| 序 | 模块 | 文件 | 代码前缀 | 提供什么 | 密度 |
|----|------|------|----------|----------|------|
| 1 | 拆解卡 | `知识库/副官拆解/YYYY/MM/SRC-*.md` | SRC-YYYYMMDD-NNN | 六维提炼（新增信息/认知/行业谈资/待研究课题/未知扫描/行动与回链）——最高价值入口 | 高 |
| 2 | 原始稿 | `原始素材/录音转写/YYYY/MM/*_raw.md` + `_clean.md` | SRC 同号 | 原文金句、逐字口径、说话人映射 | 高（取金句用） |
| 3 | 实体索引 | `知识库/实体索引/entities.md`、`relations.md` | PER-/ORG-/PRJ-/PLC- | 实体画像、别名列（含 ASR 误记修正）、关系与置信度 | 高 |
| 4 | 认知演化 | `知识库/认知演化/evolution.md` | INS-YYYYMMDD-NNN | 一句话认知+修正历史（用户后补确认往往只在这里） | 中高 |
| 5 | 待办 | `待办管理/OPEN.md` | T-YYYYMMDD-NNN | 主题相关行动项、优先级、截止日、涉及人物 | 中高 |
| 6 | 副官主线 | `副官系统/data/operating_state.json`、`主线台账.md`、`视图/驾驶舱.md` | LINE-YYYYMMDD-NNN | 主线状态机（S0_S1…）、决策门、成功定义、next_action | 中高 |
| 7 | 状态与更正 | `交接手记/CURRENT_STATE.md` | — | 「已确认的重要人脉/信息更正」节=全库更正权威；待确认清单 | 高（必读） |
| 8 | 日志/人脉/日程 | `工作日志/YYYY/MM/*.md`、`人脉管理/<姓名>.md`、`日程管理/UPCOMING.md` | — | 时间线细节、接触窗口、人物角色 | 中 |

grep 技巧：关键词一次多给（主题词|别名|机构|人名），`search_files(files_only)` 先看命中文件分布，再决定精读清单；命中>60 文件时按"拆解卡/实体/状态"三组二次收敛。

## 2. 输出 schema（素材包分节）

```
# <主题>素材包
> 生成日期 / 仓库路径 / 说明（事实带来源、事实与推断分开、待确认标注）
## 一、<定位与股权/主体>      （主体是谁、股权/角色、牵头人）
## 二、<技术与产品>          （技术背景、产品参数、合作方）
## 三、<市场与订单>          （客户、订单池、渠道）
## 四、<资金与成本>          （注册资本、成本测算、缺口、换股/融资安排）
## 五、<时间线与里程碑>      （表格：日期|节点|来源；标注"努力目标非承诺"）
## 六、<落地决策>            （注册地/主体选择之争、决策门状态、接触窗口）
## 七、<待确认项与敏感项>    （编号待确认清单 + 敏感项/风险，敏感项单独强调）
## 八、<金句>               （原文+发言人+日期，编号引用）
## 附：来源文件清单          （本包引用的全部文件路径）
```

## 3. 标记约定

- `【事实｜F1】` 库内 confirmed_fact/原文可直接引用 → 后跟 `来源：<路径>（SRC-xxx，日期）`
- `【推断】` ai_inference/user_judgment/third_party_view 或整理者归纳 → 注明库内置信度（如"高置信度"）
- `【待确认】` 库内 UU/KU 未决项；敏感项（口头披露口径、含原"代持/干股"诉求的方案文档、税务/合规结论）单列并注明"引用前必须核实"
- 每条事实必带来源；金句必须带发言人+日期（用 raw 原文，不用 clean 改写）

## 4. 旧素材口径陷阱（2026-08-19 实战）

- 主题跨多日时，旧 SRC 术语已被后续更正：一保研究院→中材（南京）矿山研究院、民防雷达→矿山边坡雷达、B轮/B+轮命名（2026-08-19 统一为上一轮=B轮、本轮=B+轮）。
- 规则：写包前先读 CURRENT_STATE「已确认的重要人脉/信息更正」节；实体别名列（entities.md"别名"字段）是第二权威；更正后术语全包统一，旧名出现处注"（旧称，已更正）"。
- 同一主题往往存在两套并行口径（如 PRJ-003 波总60%/研发40% vs 跃壹 泽天51% 架构）——不要替仓库裁决，两套都列并标"对应关系待核"。

## 5. 成稿与验证

- 写 `/tmp/<topic>_collect.md`（不走对话输出，20-40KB 级）。
- 验证：`wc -l` + `grep -c '【事实】'` / `grep -c '【推断】'` / `grep -c '待确认'` 报数。
- 交付回执：分节要点摘要 + 最大信息缺口清单 + 未改动仓库声明。
