# 尽调答复流水线（Due Diligence Response）

## When to Use

- 银行/机构/监管方向泽天发来问题清单（如银行尽调10问），要求出初步答案
- 波总说「先出初稿」「可交接」「给另一个 AI」「找数据去挖掘」
- 波总问「你能读取到公司财务数据吗」——本质是问数据可得性，先盘点再答
- 与 corporate-due-diligence（尽调别人）相反：这是**己方被尽调**的方向

与 corporate-due-diligence（尽调别人）相反的方向：**己方被尽调**。银行/机构向泽天发来问题清单，波总要求先用本机现有素材出初稿，再产出一份可交接文档给下一个 AI 接力补数据。

## 触发条件

- 关键词：「先出初稿」「可交接」「给另一个 AI」「找数据去挖掘」

## 核心流程（2026-08-24 实测，银行尽调10问场景）

### 阶段0：数据可得性盘点（先于写作，禁止跳过）

1. 搜本机知识库：`~/AI_Workspaces/Cangjie_OBS_Notes/`
   - 重点子目录：`原始素材/录音转写/2026/08/`、`_Library(转载）/`、`Memory_AI/Ingest/`、`人脉管理/`
2. 搜缓存：`~/.hermes/cache/documents/`（成都行汇报、广慧并购营等已产出文档常含关键口径）
3. 关键词轮换：营收 / 净利润 / 现金流 / 对赌 / 在手订单 / 产能 / 股权激励 / 实控人 / 4000万 / 公司名
4. 产出「数据可得性总览」矩阵：逐题标 `✅能答(带来源文件+行号) / ⚠️部分 / ❌缺口`
   - **只写挖到的真实数字，禁止推测填空**；数字带来源锚点（文件+行号）
5. 关键判断：全量尽调包（三表/合同台账/前十大客户供应商）通常在波总公司电脑 `H:\00尽调资料V1.0\`，本机只有清单线索 → 这些题标缺口并进交接清单

### 阶段1：初稿

- 结构：每题 =「初步答案」+「数据来源」+「缺口与待补」
- 身份敏感题（实控人家庭/资产/对外投资）：只写已确认事实（如唐兴=董事长），其余标「待波总提供」，不猜
- 会计分录类（如股权激励股份支付）：给会计准则标准分录模板：
  ```
  ① 授予日/等待期分摊：借：管理费用（或研发费用） 贷：资本公积-其他资本公积
  ② 行权时：借：银行存款 资本公积-其他资本公积 贷：实收资本 资本公积-资本溢价
  ```
  注明金额需财务按激励计划公允价值测算（本机无此数）
- 文末加数据范围声明：「本稿基于 YYYY-MM-DD 本机素材，未使用 H:\00尽调资料V1.0 尽调包」

### 阶段2：交接文档（给下一个 AI 的接力棒）

1. 任务背景 + 题目原文
2. 已完成覆盖（逐题：已答/部分/缺口）
3. 数据源地图（已用文件路径清单）
4. 数据获取清单按 P0/P1/P2 优先级：
   - **P0**（缺了答不了）：三表 / 4支基金协议原文 / 合同台账
   - **P1**（大幅提质量）：实控人家庭资产、产能产量、在手订单明细
   - **P2**（锦上添花）：激励计划份额与公允价值
5. 纪律提醒：对外叙事纪律（端侧算力+RTOS 前置、军工仅背书≤2次）、估值=谈判策略非约定【策略表述】、口径冲突以最新素材为准、数字必须可溯源
6. 建议下一步动作

## 执行引擎

文档生成按波总铁律先派 Cursor CLI（`cursor-agent -p --yolo "$(cat /tmp/xxx/prompt.md)"`）；数据挖掘（只读 grep/read）Hermes 可直接做。Cursor 网络不通时如实汇报卡点，由波总决定修 Clash 还是降级 🟢Hermes 直出。

## Pitfalls

- **先盘点再动手**：数据可得性矩阵是交付物的一部分，不是内部过程——波总要拿它判断「要不要用另一台电脑」
- **禁止编数字**：无数据题写「缺口：需要XXX」，宁缺毋假
- **口径冲突**：录音转写（ASR）数字与正式材料冲突时，标注双口径，不以猜测定夺
- **身份敏感题**（婚姻/子女/资产/对外投资）：只写已确认事实，其余待波总提供
