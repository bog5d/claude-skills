# 合同/对外文件名目中性化改写

> 波总公司冲刺 IPO 时不愿留下"考虑并购"等痕迹（影响估值），但付款必须走对公+开票、开票必须挂合同、合同盖章后是硬证据。解法=把合同的服务名目洗中性，让盖章后的文件经得起查、与敏感动作无关。2026-08-23 广慧并购营 3 万信息服务合同去并购化实例。

## 触发条件
- 波总说「合同里 X 字样会被查到」「改一份没有风险的文件」「弱化这件事」「不想让人觉得我们在做 Y」+ 付款/开票/盖章场景
- 合同或对外文件含敏感标签（并购/军工/融资轮次/具体估值）需对外中立化

## 铁律 0：先对齐再动手（禁止直接改）
用户说「先统一思路」时必须先答 4 问，拍板后才执行：
1. **改名幅度**：完全去掉敏感词 vs 保留中性近义词（如"战略投资"可保留）？——给出方案 A/B/C 让用户选
2. **执行路径**：改好文本给甲方过目（默认） vs 谈新约？——决定任务书写法
3. **付款/签约主体**：用哪个公司抬头（影响合同+发票+对公账户）
4. **对账关联**：这笔款是否对应副官系统已挂的预支/待办 T- 编号（顺带更新用途标注）

## 合规边界（丑话说前面，写进对齐回复）
- **弱化 ≠ 造假**：安全线=服务描述泛化为真实存在的中性动作（信息发布/讲座/交流/考察），删敏感限定词；越过线（写成完全不存在的服务、或与实质完全无关的名目）= 虚开发票/虚假陈述风险
- 合同名目与实质完全无关是最危险的形态；"描述泛化但实质仍有一一对应"是实务普遍做法
- 用户提出具体名目方向（如"上市后规划咨询"）但存在逻辑矛盾时（公司未上市），指出矛盾并给替代项

## 设计原则（改版文本）
1. **不点具体组织名**（"广慧并购营"→"企业家交流与信息服务圈层组织"）——甲方盖章无名实尴尬，乙方不留痕迹
2. 服务内容条款逐条泛化，保留中性事实词
3. **交易要素全保留**：金额、服务期限、账户、税号、乙方空白、违约责任、盖章生效条款——一字不动
4. 不新增未授权的词（"上市/IPO/顾问"）——用户没要求就不加
5. 原文件另存新文件，**永不覆盖原件**（原件=备份+对照基准）

## 执行
- 写入动作按铁律派 Cursor（`cursor-agent -p --yolo "$(cat /tmp/prompt.md)"` 后台+notify），任务书含：源文件路径、逐条修改对照表（原句→新句）、"其余条款一律不动"清单、python-docx 另存路径、验证要求
- python-docx 改：`Document(path)` → 逐段替换 run 文本 → 保留格式（标题居中/缩进/落款）→ `save(新路径)`
- 顺手任务可打包：待办 T- 编号用途标注更新（open.md + commit + push）

## 验证门禁（交付前独立复检，不信 Cursor 自报）
```python
import docx, glob
for f in glob.glob('*.docx'):
    d = docx.Document(f)
    full = '\n'.join(p.text for p in d.paragraphs)
    for t in d.tables:
        for row in t.rows:
            for c in row.cells: full += c.text
    # ①敏感词 count==0 ②关键保留词存在 ③金额/账户在 ④标题正确
```
1. 全篇敏感词 count=0（**含表格单元格**！read_file 提取可能漏表格）
2. 保留字段复检：金额、期限、账户、税号、乙方空白
3. 全文段落逐条过目（python-docx 打全段落）确认无改歪
4. 原件备份在旁

## 交付
- 文件路径 + 修改对照表（原句→新句，逐条）+ 硬校验结果（count=0 等）
- MEDIA: 直接发文件给波总（docx 小文件 Telegram 可发）
- 附对甲话术建议：对方问"为什么改名"时的标准回答（如"准备资本市场动作，名目中性化更稳妥，服务内容不变"）

## 后续链路（交付后提醒）
发甲方讨论 → 甲方确认 → 填乙方主体+税号 → 对公付款 → 开票 → 归档 + 副官 T- 编号闭环
