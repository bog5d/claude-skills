# 可编辑 PPT 交付质量门

## 触发场景
- 波总要求「可编辑的 .pptx」（投资人路演、正式外发、发给 Codex 协作）
- 上次 PPT 被反馈「全是整页图片、0 个可编辑文字框」
- 用 python-pptx / ppt-master 改完 PPTX，交付前

## 核心铁律：禁止整页贴图

**血泪教训（2026-08）**：把页面渲染成 2880×1620 大图再整张铺到幻灯片上（"整页贴图"），视觉上能拿出手，但 14 页里 12 页变成 0 个可编辑文字框、0 个独立图片对象。投资人/协作方（Codex）直接拆包判定「不具备真正 PPT 编辑能力，4/10 分」。

**根因**：走了 HTML 渲染 → 整页截图 → 贴图 的捷径，把「视觉完成度」当成「任务完成度」。省掉逐元素坐标活，代价是把「可编辑 PPT」偷换成了「图片画册」。

**铁律：**
1. 所有标题、正文、数字 = 真文本框（`add_textbox`），禁止转图
2. 所有图片 = 独立 PICTURE 对象（`add_picture`），禁止整页背景图
3. **交付前必须跑结构自检**：`scripts/verify_editable.py <file.pptx>`，检测到整页图（宽>85% 页面宽 且 高>85% 页面高）直接判不合格、拒绝交付——用 shape_type 计数当证据，不空口说"好了"
4. 缺素材就用占位框（AutoShape 矩形 + 文字标注「待补」）诚实标注，宁缺毋假——不要从整页截图里裁图冒充独立素材

**验收口径**：打开 PPT 后每张图可单独移动、每段文字可单独修改，才算「真编辑」。视觉分靠贴图买来的不算数，可编辑性才是真底子。

## 与 Codex 的协作分工（大脑/手）

- **Codex = 大脑**：投资逻辑 / 哪页留删 / 标题结论 / 页面信息结构 / 数据口径 / 验收 / 缺什么图
- **Hermes = 手**：开 PPT / 抠图 / 调尺寸 / 搬图 / 布局 / 嵌图 / 逐页执行 / 返修

前提铁律：Hermes 这边禁掉「整页贴图」后门，用结构自检兜底。

## 素材抽取原则

- 真实素材优先从原始 PDF/PPT 提取：PyMuPDF `get_images()` + `get_image_rects()` 把图片 bbox 和文本块坐标对齐，精确定位「哪张图对应哪个产品/标签」，不要靠猜
- 视觉模型（qwen-vl-max）失效时，靠「文本块坐标 + 图片 bbox」交叉定位同样可靠
- 素材确实没有（如商业航天图在 Codex 云端的包里没发来）时，占位 + 诚实报告来源清单，不冒充、不从整页图里裁图

## 验证步骤

1. 重做页面 → `prs.save()`
2. 结构自检：`python3 scripts/verify_editable.py <file.pptx>`
3. 渲染预览（本机无 LibreOffice 时用 ppt-master 的 `pptx_to_svg.py` + cairosvg；⚠️ 单独渲染某页 SVG 时图片可能断链，最好渲染整份或直接开 PPTX 看）
4. 交付时附「文本框数 / 图片对象数 / 有无整页图」三项证据 + 素材来源清单

## 已知坑

- `pptx_to_svg.py` 单独渲染 `slide_NN.svg` 时，assets 图片引用可能断链导致预览 PNG 极小（如 18K）——这是预览工具问题，不是 PPTX 里没图；PPTX 里 `add_picture` 的图是真实嵌入的
- 中文 PPT 字体用「微软雅黑」需同时设置 east-asian 字体：`rPr` 加 `<a:ea typeface="微软雅黑"/>`，否则渲染 fallback
