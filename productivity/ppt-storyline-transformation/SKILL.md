# PPT Storyline Transformation — PPT去拼盘感改造

诊断并修复PPT的"拼盘感"——章节跳跃、内容堆砌、角色混乱、念稿感重——将其重构为连贯的故事线。

## 拼盘感四大诊断维度

### 1. 结构跳跃
症状：章节之间无过渡钩子，像模块拼接。
解法：用"为什么是现在"作为过渡桥，连接定位→赛道→产品。

### 2. 内容堆砌
症状：产品页密密麻麻列出12+型号，像产品目录而非故事。
解法：每个产品页只展示2-3个代表性案例，每个案例讲"场景+方案+优势"。

### 3. 角色混乱
症状：一份材料混了对政府/投资人/客户的不同话术。
解法：明确受众，统一语气和关注点。

### 4. 念稿感重
症状：逐字稿用"首先/接下来/接着"机械串联。
解法：用故事线串联（Hook→痛点→方案→能力→壁垒→证明→前景），过渡用自然语言。

## 工作流

### 第一步：读取现有材料
- PPT文件（.pptx）：用python-pptx读取所有slide内容
- 逐字稿（.docx/.txt）：读取完整文本
- 历史版本：对比不同版本找出反复出现的结构问题

### 第二步：诊断拼盘感根因
按四个维度逐一检查，标注具体问题页码。

### 第三步：设计新故事线
标准12页结构：
1. 封面
2. 定位（一句话定义）
3. 赛道（为什么是现在）
4. 2+1产品矩阵概览
5-6. 代表性产品（每类2-3个案例）
7. 软件/技术壁垒
8. 团队/资质壁垒
9. 里程碑/业绩
10. 客户与合作伙伴
11. 前景/融资需求
12. 封底

### 第四步：生成改造方案
输出文档：问题分析 → 改造原则 → 具体修改建议 → 新版故事线大纲 → 过渡话术模板

### 第五步：生成精简版PPT
用python-pptx生成新版.pptx，深色科技风或亮色专业风（根据用户偏好）。

## 过渡话术模板

| 页面转换 | 过渡话术 |
|----------|----------|
| 定位→赛道 | "为什么是我们，为什么是现在？" |
| 赛道→产品 | "基于这个赛道，我们做了三件事..." |
| 产品→壁垒 | "这些产品背后是什么能力支撑？" |
| 壁垒→证明 | "这些能力已经经过了什么验证？" |
| 证明→前景 | "站在今天，未来三年的增长点在哪？" |

## 陷阱

1. **不要为了精简而丢掉关键数据** — 精简的是表达方式，不是数据
2. **不要把所有产品都删掉** — 保留代表性案例，其余放在附录或口头补充
3. **逐字稿要和PPT配合** — PPT放关键词/图表，逐字稿放详细解释
4. **深色/亮色取决于用途** — 内部汇报用亮色白底，路演/对外用深色科技风
