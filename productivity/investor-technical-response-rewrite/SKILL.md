# Investor Technical Response Rewrite — 投资机构技术答复材料重写

将公司内部起草的、存在认知偏差的投资人技术答复材料，在**严格事实边界**下重新梳理改写。目标是扭转投资人的错误认知框架（如"你们是不是自己设计流片了一颗芯片"），建立正确的技术价值叙事（"你们是否掌握了完整技术体系和工程化能力"）。

## 核心原则

1. **不是润色，是认知重构** — 不改几个词，而是改投资人理解公司的方式
2. **铁的事实边界** — 改写必须在用户明确的事实边界内操作，不得自行扩张
3. **审慎权属表述** — 协议支持什么就写什么，不替公司法务越位
4. **可核验优于华丽** — 给投资人能查的证据，比给完美故事重要

## 工作流

### 第一步：接收并理解约束

用户需提供三样东西（缺一不可）：

1. **原稿** — 团队拟写的现有材料
2. **事实边界** — 什么可以写、什么不能写、什么需要法务确认
3. **公司/产品背景** — 哪家公司、什么技术、当前投资人误解是什么

### 第二步：识别认知偏差与重构目标

从原稿中找出导致投资人误解的表述，明确：

- **错误认知方向**：投资人现在以为公司是什么（如"自主芯片设计公司"）
- **正确认知方向**：应该让投资人理解公司是什么（如"完整技术体系和工程化能力的系统公司"）
- **关键认知转折点**：哪几个概念必须重新定义才能扭转方向

### 第三步：按标准结构组织正文

对外正文标准结构（参考 `references/response-structure.md`）：

1. **核心结论** (3-5段)：直接回答投资人最关心的4-5个问题
2. **技术构成说明**：不是单一器件，是多层次系统
3. **知识产权及技术来源**：区分底层技术/改进/商业秘密，附核验提示
4. **供应链说明**：外部生产 ≠ 不掌握核心
5. **外部合作边界**：高校/供应商做什么、不掌握什么
6. **核心人员与组织化沉淀**：关键人物的作用 + 去个人依赖的措施
7. **投资机构核验方式**：可提供的文件清单

### 第四步：输出双部分

**第一部分：正式对外正文**
- 完整、连续、可直接发送给投资机构
- 语气专业、克制、可信
- 不出现"根据用户提供的信息""可能是"等 AI 语言
- 不确定的权属/协议信息用 `【内部核验：请法务确认后删除】` 标记
- 2000-3000 字
- 末尾附"可供投资机构核验的文件清单"

**第二部分：内部逻辑说明**
- 仅供投融资负责人和团队学习，不对外
- 说明原稿存在哪些逻辑问题
- 说明为什么做每个关键改写决策
- 说明投资人真正关心的核心问题

## 必须避免的表述（跨公司通用）

除非有充分文件证据，不得出现：

- "所有核心技术100%自主研发"
- "完全由公司自主设计/流片/制造"
- "不存在任何外部依赖"
- "全球唯一""国内唯一""完全不可替代"
- "所有知识产权均归公司所有"

权属表述优先使用：

- "公司已依法取得相关技术及专利权益，具体权利范围以协议为准"
- "相关协议及专利证书可在签署保密协议后向投资机构开放核验"
- "公司掌握产品定义、参数体系、结构设计、供应链标准和验证能力"

## 关键概念重命名策略

当原稿中的某个概念名（如"XX芯片"）误导投资人时：

1. 首次出现时给出清晰定义："公司所称的 XX，并非单指一颗传统意义上的集成电路芯片，而是由 A、B、C、D 共同构成的功能模块"
2. 全文优先使用正确名称
3. 如果必须保留旧称，注明其为"功能性名称"而非技术分类

## 陷阱

1. **不要替公司编造能力** — 事实边界写什么就写什么，不要"合理推断"出不存在的能力
2. **不要回避硬问题** — 投资人问"芯片谁设计的"，不能说"我们有完整体系"糊弄过去。要正面回答"器件由专业供应商生产，公司掌握选型、参数、组合和验收"
3. **"商业秘密"不能成为拒绝披露的理由** — 可以对不公开参数，但必须给可核验证据（协议、测试报告、客户证明等）
4. **不要制造单一人员依赖** — 描述创始人/CTO 贡献时，同时说明公司如何将个人经验转化为组织资产
5. **不要暗示"仿制"或"复制"** — 即便事实上有参考竞品，也不在对外材料中主动提及
