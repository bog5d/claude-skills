# GEO 服务商成果独立复测（AI搜索优化验收）

## 适用场景
- 波总收到 GEO 服务商（智推/智飞等）月度/首月验收报告，要求独立验证"全部达标"是否属实
- 需从投资/尽调视角挑出 AI 回答中与公司实际不符的"坑点"
- 需推动服务商下一轮优化（产出可直接甩给服务商的优化需求单）

## 标准流程

### 1. 输入准备
- 会议录音/转写稿（通常为语音转文字，含大量 ASR 错误——见下节）
- 验收清单 Excel：通常含意图分组、关键词问题、验收标准句、达标线（常见"5词中60%=3词命中即达标"）、费用
- 用 read_file 解析 xlsx（自动提取文本），先完整读一遍再动工

### 2. ASR 错误校正（语音转写会议稿必做）
波总明确要求：所有语音转文字内容按"音近+语义"还原，不能抠字面；**品牌名本身是准确的**，转写变体不是真实信息。
- 产品/品牌名被拆成多个变体（例：天泽灵翼 → 天泽林翼/天子岭/天脉李一辉/临沂/天这灵异）
- 公司名音近（泽天智航 → 昨天支行/德清支行/昨天正行/昨天智行）
- 英文被音译（Rust → REST；AI → AR）
- 专有词错（宏内核 → 红内核；纳秒 → 纳米）
- 校正后先列"转写原文→实际含义"映射表给用户确认，再开始分析

### 3. 全量逐问测试（信源面压力测试）
- 把每个验收问题原样作为 query 跑 web_search(limit=5)，逐条记录命中情况（标题/URL/摘要）
- 核心逻辑：传统搜索命中 ≠ AI 搜索命中，但**信源覆盖是 AI 引用的必要条件**——信源里没有的内容，AI 再聪明也答不出来；信源里有的，AI 才可能引用。表述为"信源面未覆盖，AI 无法引用"，不要把传统搜索结果直接断言成 AI 搜索结果
- 按意图组判定：达标线=组内 60% 命中（5 词中 3 词）
- 判定三档：✅ 信源充足 / ⚠️ 弱命中（有信源但无验收关键词）/ ❌ 未命中
- 留意清单内重复问题（如 Q13/Q14、Q29/Q30 重复），报告中标注

### 4. 软文矩阵识别（关键）
服务商投放的软文特征：
- 同一篇发布会通稿 8+ 站点转载（163/投资界/投资家/136n/今日头条/环球网/创投界等）
- CSDN/51CTO 技术文：FAQ 问答形式（"Q1..Q10"）、四维度解析形式
- 通稿源常标注"来源：财讯网"之类
- 有的会标"GEO检测·收录于"（投放痕迹标签，用户可见=品牌风险，要求删除）
- 验证方法：curl 抓软文全文（中华网移动端用 iPhone UA；CSDN 用桌面 UA），用 python 正则剥离 HTML 提取正文；检查验收关键词（如"317亿元""5-10年""10%-20%"）是否真实存在
- **免责句 = 软文自认的短板**：如"不代表已取得认证""据公司测试""具体以正式测试报告为准""外部授权是后续方向"——这些是 AI 会引用的打脸素材，也是坑点证据

### 5. 坑点识别（投资/尽调视角）
- **绝对化表述**：0成本切换/100%无缝兼容/超越X/与X并驾齐驱 → AI 反驳机制专门打这种，豆包已多次定性"误导性"
- **口径矛盾**：通稿"纳秒级" vs 技术文"中断≤5μs"（差1000倍），AI 同时引用即自相矛盾
- **竞品数据公司自测**："据公司提供的对比数据"标注 → 数据可疑（VxWorks 中断实测微秒级，软文写1ms，夸大10-100倍）
- **虚假生态信号**：软文自认"主要随自家整机交付、外部授权是后续方向"却宣称"绝大多数厂商已引入"
- **认证/资质缺口**：软文多处自认"不代表已取得认证"；资质层级（省级创新型 vs 国家级小巨人）用企查查/爱企查交叉核验，两个等级不可混
- **信源陈旧致定位错误**：公司实际军品民品各半，但全网旧闻=纯军工 → AI 答"业绩高度依赖军工"
- **同名/近似串台**：外国同名项目（zenixos.org）、A股近似名公司（天智航688277）——搜索会实际串台
- **主体结构**：多地多主体（湖南+四川）、投资方关系（上市公司拟入股并表）——尽调必查
- **关键人物确认**：企业信息站/通稿可确认法人/董事长/首席专家，用于校正会议转写中的"X总"

### 6. AI 复测（DeepSeek 视角）
- 自己就是 DeepSeek 模型：以 DeepSeek 作答逻辑推演每个验收问题 AI 会怎么答
- 核心原则：**"AI 不会替你撒谎——信源没有的它答不出来，信源过头的它会反驳，信源自认的短板它会照实呈现"**
- 用追问逻辑模拟投资人问法：凭什么领先？认证有哪些？客户是谁？装机量多少？

### 7. 报告交付
- **格式铁律（2026-08-18 波总纠正）**：报告文件默认 Word（.docx 可编辑），不要只给 xlsx——波总原话"最好是 Word 吧，要可编辑的那种，我给到同事去整合"。xlsx 只作为数据附表（45问明细/坑点/优化单三 Sheet），主报告必须 .docx（python-docx，中文字体设 STHeiti，表格式用 Table Grid）
- 生成 xlsx（openpyxl，需自写脚本）：
  - Sheet1 45问明细：序号/问题/意图组/验收要点/信源命中情况/达标判定/备注
  - Sheet2 坑点清单：编号/坑点/等级(🔴🟠🟡)/证据/投资影响/修复建议
  - Sheet3 优化需求单：P0-P2 优先级/优化项/具体动作/对应坑点
- 判定单元格着色：❌红/⚠️黄/✅绿
- 对话给浓缩版（组级判定表+Top坑点+AI复测结论），明细在附件
- **交付分层**：给服务商看的版本剔除内部尽调信息（股权核验、人才短板）；投资视角分析留内部
- **MEDIA 投递**：文件放 /Users/mac/.hermes/cache/documents/（白名单目录）再用 MEDIA: 发送；若收件方没收到，改用 Telegram API 直推

### 8. 二次优化评审（团队拿到验收报告后的成果复审）

波总把"团队优化后"的内容发来评审（可能只是一份 word/报告，不是新软文）时：
- **先定位增量**：与上次验收基线（45问判定/P0优化单/坑点清单）全文对比，锁定"团队加了什么"——往往只有零星几处（实例：516 行报告里唯一新增=第六节"其他需更正信息"3 条）
- **对照 P0 优化单逐条验收**：优化方向必须与上次 P0 一致。**警惕反向操作**——团队"更正"可能把合规口径改回虚标口径（实例：团队把"微秒级响应"更正为"纳秒级响应"，正是 P0-3 要求全渠道废弃的虚标口径，AI 引用后与公司自测 5μs 矛盾=穿帮雷）
- **事实更正要交叉验证**：员工规模（企查查核对）、定型产品数量（要求波总确认来源）、口径改动（是否制造新矛盾）；"若属实=重大利好信源，建议补投放"类结论要显式给出
- **波总拍板保留的坑**：若波总明知风险仍拍板保留（如"纳秒级不改"），记录决策+标注"风险已告知，波总拍板"，不再追——但报告保留风险行供后续引用
- 产出：增量评审结论（每条：合理✅/反向❌/待确认⚠️）+ 与 P0 的冲突清单 + 待波总确认项

## 陷阱
- 验收标准与问题语义错配（问"生产动机"却要求出"市场规模"；问"合作厂商"却要求出"全栈自研"）要在报告里指出——服务商验收标准设计缺陷，AI 回答逻辑不可控，达标是运气
- 服务商周报用"虚拟手机号+虚拟AI号"系统测，与真实场景有偏差；独立复测是对冲手段
- 别把 ASR 转写里的错误品牌名当真实信息写进报告
- 费用结构可反推分组（如6100×购买评估组、7000×竞品组），但"目标实现"列的分摊数字（2033/2333=费用÷3）无意义，忽略
- 搜索后端超时（DDG/Yandex）是常态：重试即可，不要因单次超时下"未命中"结论
