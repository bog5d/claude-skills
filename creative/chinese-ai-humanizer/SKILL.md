写作或润色中文时，检查并去除以下 AI 痕迹，保持表达自然、直接、简洁。

# 喜欢用不是... 而是... 的句式
例如：不是糊弄人的视觉特效，是真在做物理。

# 喜欢用“ ”来包裹某些比喻或名称
例如：它把"提醒你休息"从功能问题变成了审美问题。

# 喜欢用 —— 符号

比如：视界、光子环、吸积盘、被弯曲的字——都是光线追踪出来的涌现结果，没一个是手动画上去贴上去的。

# 喜欢滥用比喻

比如：没用任何"重武器"——没 daemon、没 IPC、没文件监听——就靠一个标准的终端转义码和一个 16 位签名，做到了实时、低延迟、零冲突。

# 简洁表达时，喜欢用如下不太符合人类表达习惯的句式

比如：安装后就**直接跑**。 学完可以**直接挂** LinkedIn 求职。

# 喜欢用一个疑问句加一个回答
比如：家公司里最值钱的是什么？是数据库里那堆表。

# 数字部分经常用逗号
比如：100,000, 正常人类打字不会很精确的中间加逗号

# 逗号经常使用英文豆包
比如：某段对话,几秒就出来。

# 非常喜欢大批量罗列很多名称，不如使用 ... 等等省略。
比如：它把网站 Widget、邮件、WhatsApp、Facebook Messenger、Instagram、X、Telegram、LINE、SMS、TikTok 这些渠道全部聚合到一个收件箱里。
期望：它把WhatsApp、Instagram、X、TikTok 等等这些渠道全部聚合到一个收件箱里。

# 喜欢用 “一句话讲清楚：” 句式
比如 badcase：它干的事情用一句话讲清楚：把任何网页，变成 AI 能直接吃下去的干净 Markdown 或结构化数据。
期望 goodcase：它能把任何网页，变成 AI 能直接读取的干净 Markdown 或结构化数据。

# 喜欢用 “这件事” 的句式
比如 badcase：它把写中国专利交底书这件事拆成了流水线，从读代码到出 Word，全流程自动化。

# 喜欢用“,”英文标点而不是“，”中文标点
比如：做出 browser-use 的那个团队,最近又开源了一个新项目.
期望：做出 browser-use 的那个团队，最近又开源了一个新项目。
