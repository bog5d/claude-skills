# Content Research Writer

**核心价值：每步确认，不返工。** 不会一口气写完三千字让你推翻重来——在每个关键节点停下来等你点头。

## When to Use

触发条件：
- "写一篇文章关于..."
- "帮我写一篇推送/博客/公众号文章"
- "写个关于 XX 的内容"
- "帮我整理一篇..."

**触发后，本 Skill 接管整个写作流程，自动走完 6 个阶段。**

## 与其他 Skill 的关系

| 阶段 | 使用的 Skill/工具 |
|------|------------------|
| 资料搜集 | web_search, web_extract |
| 大纲规划 | 本 Skill |
| 分段写作 | 本 Skill |
| 资料验证 | web_search, web_extract |
| 去AI味 | humanizer（自动加载） |
| 标题诊断 | 本 Skill（内置标题公式库） |

---

## 完整流程：6 阶段 + 确认门

```
Phase 1: 搜资料 ──→ Phase 2: 出大纲 ──[确认]──→ Phase 3: 分段写 ──[逐段确认]──→
Phase 4: 验证补充 ──→ Phase 5: 去AI味 ──→ Phase 6: 出标题 ──→ 交付
```

### 确认门规则

**必须停下等用户确认的节点（共 3-4 个）：**
1. 大纲出来后——改结构代价最大，必须确认
2. 每段写完后——用户说「继续」才往下
3. 全文初稿完成后——问要不要调整结构
4. 标题诊断后——让用户从候选里选

**不停、自动处理的：**
- 措辞微调、错别字修正
- 资料补充（自动搜，搜完展示但不中断）
- 某一段的小修改（用户说「这段改一下语气」→ 改完继续）

---

## Phase 1: 资料搜集

**目标：快速建立对话题的基本认知，收集 3-5 个高质量信息源。**

步骤：
1. 理解用户的选题——如果选题模糊，先用 1-2 个 clarifying question 锁定范围
2. `web_search` 搜索相关话题（2-3 次不同角度搜索）
3. `web_extract` 提取 3-5 个最有价值的页面内容
4. 整理成「资料摘要」：

```
## 资料摘要：{选题}

### 关键事实
- [事实1] — 来源：[链接]
- [事实2] — 来源：[链接]

### 主流观点
- [观点1]
- [观点2]

### 争议/不同声音
- [争议点]

### 数据点（带来源）
- [数据1]（[来源]）
- [数据2]（[来源]）
```

5. 直接进入 Phase 2，不停下确认。

---

## Phase 2: 大纲规划 【确认门 #1】

**目标：出结构，锁定方向。这是最关键的确认点——结构错了后面全白写。**

步骤：
1. 基于资料摘要，设计文章结构（3-5 个部分 + 引言/结论）
2. 用以下格式展示大纲：

```
## 大纲：{标题占位}

### 引言（~200字）
- 钩子：[用什么东西抓住读者]
- 背景：[为什么现在写这个]
- 承诺：[读完能获得什么]

### 第一部分：{小标题}（~500字）
- 核心观点：
- 用到的资料：[来源1], [来源2]
- 需验证：[标注哪些观点需要搜索验证]

### 第二部分：{小标题}（~500字）
- 核心观点：
- 用到的资料：
- 需验证：

### 第三部分：{小标题}（~500字）
...

### 结论（~200字）
- 核心信息：
- 行动建议/悬念：
```

3. **停下来等用户确认。** 用户可能：
   - 「可以，继续」→ 进入 Phase 3
   - 「第二部分换一下，应该讲XX」→ 修改大纲后重新展示
   - 「加一个XX部分」→ 加上后再确认
   - 「结构不对，重来」→ 重新出大纲

4. 用户确认后才进入 Phase 3。**不要跳过这一步。**

---

## Phase 3: 分段写作 【逐段确认门 #2】

**目标：一段一段写，每段确认后往下。不会写到第三段发现第一段方向错了。**

步骤：
1. 按大纲顺序，逐段写作
2. 每段写完后展示：

```
### {小标题}

{段落正文}

---
✅ 这一段写完了。继续下一段？或者要改什么？
```

3. 用户回应：
   - 「继续」→ 写下一段
   - 「改一下XX」→ 原地修改，再问
   - 「这段不要了」→ 跳过
   - 「从头改结构」→ 回到 Phase 2

4. 每一段写作时注意：
   - 引用 Phase 1 收集的资料，标注来源
   - 对大纲中标注「需验证」的观点，先写草稿，等 Phase 4 验证
   - 保持段落间的逻辑衔接

**写作风格默认设定：**
- 口语化，像在跟朋友聊天
- 不要新闻联播腔
- 不要「首先其次最后」的刻板结构
- 可以有个人的犹豫和不确定（「说实话，我自己也还在摸索」）
- 避免用力过猛的比喻和空洞升华

---

## Phase 4: 资料验证 【自动，不中断】

**目标：把大纲中标注「需验证」的观点逐一核实，补数据、补出处。**

步骤：
1. 扫描全文，找出所有「需验证」的观点
2. 每个观点去 `web_search` 搜索验证
3. 返回验证结果：

```
## 资料验证结果

| 观点 | 状态 | 说明 |
|------|------|------|
| 「XX行业增长30%」 | ✅ 有数据支撑 | 来源：XX报告2025 |
| 「YY技术是趋势」 | ⚠️ 部分支撑 | 有讨论但无定论 |
| 「ZZ公司已经做到」 | ❌ 未找到来源 | 建议删除或改措辞为「据称」 |
```

4. 根据验证结果自动修改文章（补数据、删无来源观点、改措辞）
5. 展示修改后的全文，问：「验证完了，有两处改动。要看看吗？」

**如果验证发现重大漏洞**（比如核心论点被推翻），停下来等用户决策。

---

## Phase 5: 去AI味

**目标：用 humanizer 规则扫一遍，去掉 AI 痕迹。**

步骤：
1. 自动加载 `humanizer` Skill 的规则
2. 扫描全文，标注 AI 痕迹：

```
## 去AI味扫描

| 位置 | 问题类型 | 原文 | 建议 |
|------|---------|------|------|
| P3 | 强调重要性 | 「这是一个重要的里程碑」 | → 删掉，直接说事 |
| P5 | -ing短语 | 「标志着行业进入新时代」 | → 改成具体数据 |
| P7 | 规则三滥用 | 「更快、更好、更强」 | → 去掉两个 |
| P8 | 中文特化：三段式 | 「第一...第二...第三...」 | → 删掉序号，自然连接 |
```

3. 应用修改，展示润色后的全文
4. 不停下确认（用户可以喊停）。

---

## Phase 6: 标题诊断 【确认门 #3】

**目标：基于文章类型和内容，推荐合适的标题公式。**

步骤：
1. 判断文章类型：教程 / 观点 / 案例 / 方法论 / 清单 / 故事
2. 从标题公式库中匹配类型，生成 3-5 个候选标题
3. 每个候选附带推荐理由和适合的平台

### 标题公式库（精选 12 个高频公式）

| # | 公式 | 适合 | 示例 |
|---|------|------|------|
| 1 | 数字+结果 | 教程/方法论 | 《3个步骤，让你的文章阅读量翻倍》 |
| 2 | 痛点+解决方案 | 观点/教程 | 《写文章总是从零开始？试试这个流水线》 |
| 3 | 反常识/反转 | 观点 | 《装了30个AI Skill后，我只留了5个》 |
| 4 | 身份+场景+收益 | 教程 | 《给内容创作者的一套从写到发工作流》 |
| 5 | 对比/Before-After | 案例/观点 | 《从3小时到30分钟，我的写作流程变了》 |
| 6 | 提问式 | 观点 | 《你的文章读起来像AI写的吗？》 |
| 7 | 「怎么」/「如何」型 | 教程 | 《如何用5个Skill串起一条写作流水线》 |
| 8 | 否定式/排除法 | 观点 | 《不是工具越多越好》 |
| 9 | 数据+冲击 | 案例/观点 | 《75个标题公式，只有这3个最管用》 |
| 10 | 「为什么」型 | 观点 | 《为什么技能越多，效率反而越低？》 |
| 11 | 结论前置 | 观点 | 《Skill越多，心流越少》 |
| 12 | 悬念/好奇 | 故事/观点 | 《我删了25个Skill，才发现这个真相》 |

4. 展示候选标题：

```
## 标题推荐

文章类型：【观点+方法论】

1. 【数字+结果】《装了30个AI Skill后，我只留了5个》
   适合：公众号/知乎 | 理由：好奇+数据双重钩子

2. 【痛点+方案】《写文章装了一堆Skill还是不会用？串成这条流水线就行了》
   适合：小红书/即刻 | 理由：精准打击痛点，解决方案直接

3. 【反常识】《Skill不是越多越好——从写到发的5步工作流》
   适合：公众号/掘金 | 理由：反常识引发讨论

4. 【怎么型】《如何用5个Skill打造从写到发的内容流水线》
   适合：知乎/少数派 | 理由：SEO友好，长尾流量

5. 【结论前置】《心流比工具更重要：我的内容创作工作流》
   适合：即刻/微博 | 理由：观点鲜明，适合碎片阅读
```

5. **停下来等用户选标题**（或让用户自己改）。

---

## 交付

全部阶段完成后，输出最终成果：

```
## 📝 最终交付

**标题**：{选定标题}
**字数**：{总字数}
**资料源**：{N} 个
**验证通过**：{百分比}

{全文}
```

---

## 快捷模式

如果用户说「快速写一篇，不需要一步步确认」，跳过所有确认门，直接走完 6 个阶段一气呵成。

如果用户说「已经有初稿了，帮我校对+去AI味+出标题」，直接从 Phase 5 开始。

---

## Phase 4 适用性说明

Phase 4（资料验证）针对的是**有外部事实依赖**的文章——教程、方法论、案例分析等需要引用数据和来源的内容。对于**个人叙事、工作流介绍、经验分享**类文章，Phase 4 可能没有标的物，此时自然跳过，不强行补验证。

---

## Pitfalls

1. **不要在 Phase 2 确认前开始写正文**——结构错了全白写
2. **大纲必须匹配用户的实际角度，不要默认用通用框架**。用户说「介绍我们的工作流」就别给「行业综述」式的大纲。Phase 1 结束时先问自己：用户想写的到底是什么？是通用科普还是展示自己的做法？如果拿不准，在 Phase 2 出大纲前先问用户确认角度。
3. **每段不要太长**——控制在 300-600 字，方便用户快速扫完确认
4. **不要编造数据和来源**——Phase 4 验证不通过的数据，要么删，要么标「据称」
5. **去AI味不要过度**——有些排比是作者有意为之，人类也会用排比。只删「一看就是AI模板」的套话
6. **标题不要替用户决定**——给候选，让用户选。即使你强烈推荐某一个，也要给其他选项
7. **第一次写就按这个流程走。别跳过 Phase 1 直接编。**
